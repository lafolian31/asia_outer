# 화면·저장·권한 구조

## 화면

| 화면 | 내용 |
| --- | --- |
| 홈 | 요약 숫자와 최근 기록·계획·자료 조회 |
| 농장계획 | 연도·기간·상태별 계획 조회, 관련 농작업/운영 기록 바로 작성, 시간순 연결 기록·사진, 기존 완료 처리 |
| 농작업일지 | 기록하기 버튼, 접을 수 있는 빠른 기록 도구(사진 우선·작업 바로가기·복사), 2단계 작업 선택, 자동 제목, 사진·선택 메모, 작물·장소·기간·대분류·세부작업 필터 |
| 운영·교류 | 회의·운영/교육·견학/행사·교류/판매·홍보/나눔·봉사/자재·행정 기록, 사진·참여자·계획 연결 |
| 자료함 및 관리 | 문서·사진·링크, 자료 분류·검색·다운로드. 관리자에게는 농장 관리 진입 버튼 제공 |
| 농장 관리 | 농장 설정, 농작업 선택 목록·자료 분류 관리, 초대·권한, 사용량·백업·휴지통·미완료 첨부 복구 |

모바일은 하단 탐색 메뉴, PC는 왼쪽 메뉴를 사용합니다. 표시 시간대는 Asia/Seoul입니다. 기록의 날짜는 날짜형, 생성·수정·완료 시각은 타임존을 포함하는 서버 시각으로 보관합니다.

## 데이터

- `farm_settings`: 한 농장의 이름·구역·작물, 설정 버전, `work_catalog` 대분류→세부작업 JSON 목록과 자료 분류. 작업 목록 변경은 관리자 전용이며 참여자는 검증 RPC로 작물 이름을 추가할 수 있습니다.
- `members`: Auth UUID와 표시 이름, `admin/editor/viewer`, 접근 활성 여부. 이메일·비밀번호는 앱 테이블에 복제하지 않습니다.
- `entries`: `log/plan/resource`별 공통 기록. `log`의 `record_type`이 `activity`이면 운영·교류, `farm` 또는 기존 `NULL`이면 농작업일지로 조회합니다. `work_group/work_task`, `activity_category`, `quantity/quantity_unit`, `participant_ids`를 추가했습니다. 기존 분류는 추정해 채우지 않습니다. 일지 하나의 `plan_id`는 계획 하나를 참조하며 목표 연도와 실제 작업일은 별도입니다. 기존 사진·댓글·작성자·보안 경로를 재사용합니다.
- `entry_comments/entry_reactions`: 작업일지·운영 기록·자료의 댓글 및 1인 1개 감정표현. RLS 및 검증 RPC로 작성·수정·삭제 권한을 검사합니다.
- `assets`: 비공개 파일의 경로·원본 이름·크기·형식, 업로드 확정 여부. 경로에 사용자 입력 파일명을 사용하지 않습니다.
- `invitations`: 이메일에 연결된 7일 유효 일회성 코드의 SHA-256 해시. 원문은 생성 직후에만 표시합니다.
- `audit_log`: 처리 대상·작업·계정·시각. 내용 전체의 버전 이력을 보관하는 문서 버전 관리 기능은 아닙니다.

DB 스키마와 서버 검증은 `supabase/migrations`의 날짜순 SQL 파일에 있습니다. 새 설치에는 모두 실행하고 기존 설치에는 새 파일만 적용합니다. 선택형 기록은 `202610190002_selectable_work.sql`입니다. 로컬 부트스트랩 SQL은 테스트 서버의 기반 역할만 만들며 hosted Supabase에서는 실행하지 않습니다.

## 권한

| 역할 | 조회 | 등록 | 수정·휴지통 이동 | 관리 |
| --- | --- | --- | --- | --- |
| 관리자 | 전체·휴지통 | 가능 | 전체 | 설정·초대·역할·복원·영구 삭제·백업 |
| 참여자 | 활성 공동 기록 | 가능 | 본인 작성 항목 | 불가 |
| 열람자 | 활성 공동 기록 | 불가 | 불가 | 불가 |
| 비참여자·접근 해제 계정 | 불가 | 불가 | 불가 | 불가 |

버튼 외에도 DB의 RLS, 검증 RPC, Storage RLS에서 검사합니다. 앱 테이블의 직접 쓰기는 차단합니다. 작성자·생성 시각·완료 처리자·수정 버전은 서버에서 결정합니다. 마지막 관리자의 역할·접근을 해제할 수 없습니다. 첫 관리자는 서비스 소유자가 별도 SQL로 지정합니다.

JWT에 오래 남는 역할 값 대신 매 요청에서 현재 `members`를 확인합니다. 역할 변경·접근 해제 후 다음 서버 요청부터 적용됩니다. 앱은 새로고침·포커스 복귀·주기 조회에서 화면을 갱신합니다. 이미 내려받은 파일이나 화면을 캡처한 내용까지 회수할 수는 없습니다.

## 저장 보호

기록·설정의 버전을 비교하여 동시 수정 충돌을 알립니다. 저장 버튼은 진행 중 잠기며 UUID와 초기 버전 검증으로 같은 요청의 중복 생성을 막습니다. 인터넷 단절이나 실패 시 열린 입력창을 유지합니다. 창 닫기·브라우저 새로고침까지 복원하는 오프라인 초안 기능은 없습니다.

첨부는 예약 → 실제 업로드 → 크기 검증·확정 순서입니다. 본문 저장과 파일 전송은 하나의 DB 트랜잭션이 아니므로 일부만 성공할 수 있으며, 이때 성공으로 표시하지 않고 남은 파일 재시도를 안내합니다. 중단된 첨부는 관리 화면에서 확인·정리할 수 있습니다.

사진은 브라우저에서 긴 변 1,600px·JPEG 품질 0.78로 변환하며, 압축 후 2MiB 이하로 제한합니다. 문서는 10MiB 이하, 항목당 첨부 10개, 앱 전체 예약 용량 900,000,000바이트를 적용합니다. 서버가 예약을 직렬화하고 Storage에 실제 크기를 검증하여 동시 업로드나 허위 크기 입력으로 한도를 우회하지 못하게 합니다.

삭제는 기록의 휴지통 이동입니다. 일반 참여자는 휴지통 기록·사진에 접근할 수 없으며 관리자가 복원하면 함께 돌아옵니다. 영구 삭제는 제목을 다시 입력해야 하며, 연결된 일지가 있는 계획은 일지를 먼저 분리해야 합니다.

파일은 public 버킷을 사용하지 않고 앱에서 매번 로그인 권한으로 다운로드합니다. 앱은 공개 파일 주소·공유용 서명 URL을 만들지 않습니다. 문서 링크는 http/https만 허용하고, CSV는 UTF-8 BOM과 수식 주입 방지를 적용합니다.

## 빠른 기록과 호환성

작업 선택 시 ‘작물 · 세부작업’ 제목을 만들며 직접 제목을 바꿀 수 있습니다. 사진 우선 기록은 분류·메모 없이 임시 정보 상태로 저장한 뒤 같은 기록을 수정해 보완합니다. DB에는 사진 업로드 전 기록이 먼저 만들어지므로 기존 첨부 실패 복구 경로를 그대로 사용합니다. 작업량·단위·참여자는 선택 항목입니다. 최근 작물·장소는 계정별 기기 설정으로만 기억하며, 기록 자체는 서버에 저장됩니다. 이전 기록 복사는 날짜를 오늘로 설정하고 새 ID/작성자를 서버가 부여하며 사진·댓글·기존 작성자 정보는 복제하지 않습니다.

사진 목록 미리보기는 화면에 가까운 카드만 로그인 권한으로 내려받고, 화면 종료 시 blob URL을 해제합니다. 공개 사진 URL이나 유료 이미지 변환 서비스를 만들지 않습니다. 계획 상세의 연결 기록은 농작업/운영을 모두 날짜순으로 보여주며 기록 연결만으로 계획을 완료하지 않습니다. 선택형 SQL 적용 전에는 기존 필수 입력 방식과 조회를 유지하고 운영 기록 생성을 비활성화해 잘못된 분류 저장을 방지합니다.
