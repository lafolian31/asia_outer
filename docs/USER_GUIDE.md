# 함께그린 간단 사용 안내

접속 주소는 https://asia-outer.pages.dev/ 입니다. 현재 실서버 검수를 진행 중입니다. 초기 관리자의 앱 로그인은 Supabase Authentication → Users에서 직접 생성한 계정의 이메일·비밀번호를 사용합니다. Cloudflare 계정이나 DB 비밀번호와는 별개이며, 공통 기본 비밀번호는 없습니다.

## 관리자: 첫 설정과 참여자 초대

최초 서비스 소유자는 [배포 안내](DEPLOYMENT.md)에 따라 본인을 관리자 계정으로 지정합니다. 앱의 **농장 관리 → 농장 설정**에서 농장 이름·구역·작물을 바꿉니다. 쉼표로 여러 구역·작물을 구분할 수 있습니다.

초대는 자동 메일을 보내지 않는 절차입니다.

1. 서비스 소유자가 Supabase → Authentication → Users → **Add user**에서 대상자의 개별 이메일·임시 비밀번호로 계정을 생성합니다. 확인 완료 상태를 사용합니다. 비밀번호를 채팅·소스·공용 문서에 기록하지 않습니다.
2. 앱의 **농장 관리 → 참여자 초대 코드 만들기**에서 같은 이메일과 초기 권한을 선택합니다. 보통 `참여자`, 보기만 할 사람은 `열람자`입니다.
3. 생성된 코드, 실제 접속 주소, 계정 안내를 대상자에게 안전한 방법으로 직접 전달합니다. 본 앱은 전송하지 않습니다. 코드는 해당 이메일 계정에만 유효하고 7일 이내 한 번 사용합니다.
4. 대상자가 로그인한 후 표시 이름과 초대 코드를 입력합니다. 로그인했다는 사실만으로는 농장 자료에 접근할 수 없습니다.
5. 첫 로그인 후 화면 위 **열쇠 아이콘 → 비밀번호 변경**으로 본인만 아는 12자 이상 비밀번호를 설정합니다.

이메일 자동 재설정 기능은 없습니다. 잊어버린 비밀번호는 소유자가 Supabase 관리 도구로 재설정하고 안전하게 전달합니다. 이후 외부 SMTP를 도입할 때는 무료 조건·발송 제한을 확인해야 합니다.

**농장 관리 → 참여자와 권한**에서 관리자·참여자·열람자로 바꾸거나 접근을 해제할 수 있습니다. 마지막 관리자는 해제할 수 없습니다. 탈퇴자의 기존 기록 작성자 표시는 유지됩니다. 재참여는 새 초대 코드를 쓰는 대신 관리자가 접근 복구를 합니다.

## 작업자: 일지와 사진

1. **작업일지 → 일지 쓰기**에서 작업 날짜·제목·한 일과 결과를 입력합니다.
2. 구역·작물과 관련 계획은 선택 항목입니다. 계획을 선택하지 않으면 `계획 외 작업`입니다.
3. **사진 추가**에서 휴대전화의 사진 선택기를 엽니다. 기기에 따라 카메라 촬영 옵션을 선택할 수 있습니다. 카메라 옵션이 없으면 카메라 앱에서 촬영한 후 사진을 선택합니다.
4. **저장하기**가 끝난 후 목록에서 확인합니다. 다른 참여자는 새로고침하거나 화면으로 돌아와 같은 자료를 봅니다.
5. 상세 화면의 **수정하기 / 휴지통으로**는 본인 기록과 관리자에게 표시됩니다. 삭제된 기록은 관리자가 복원합니다.

사진은 JPG·PNG·WebP를 지원하고 긴 변 1,600px의 JPEG로 압축합니다. HEIC는 지원하지 않으므로 휴대전화에서 JPG로 변환하거나 카메라의 호환 형식을 사용하세요. 기록당 첨부 최대 10개, 압축 사진 2MiB, 문서 10MiB입니다. 위치 등 원본 EXIF 정보 보관을 목적으로 하는 기능은 아닙니다.

저장 실패·인터넷 단절 때 입력창을 닫지 마세요. 입력을 그대로 두고 연결 후 재시도합니다. 파일 일부만 실패했다면 안내에 따라 남은 파일을 저장합니다. 페이지를 새로고침하거나 닫으면 미저장 입력이 사라질 수 있습니다. 다른 사람이 먼저 수정했다는 메시지가 나오면 본인의 내용을 별도 메모한 뒤 최신 기록을 다시 열어 반영합니다.

## 연간 계획과 실적

1. **연간 계획·실적 → 계획 세우기**에서 목표 연도·예정 기간·내용을 입력합니다.
2. 작업자는 일지에 해당 계획을 연결합니다. 다른 사람이 만든 계획에도 본인 일지를 연결할 수 있습니다.
3. 일지를 연결한 것만으로 완료되지는 않습니다. 계획 작성자 또는 관리자가 상태를 `완료`로 바꾸면서 **실제 실행일과 결과 요약**을 입력합니다. 처리자와 시각은 자동 기록됩니다.
4. 계획 상세에서 실행 결과와 연결 일지·사진을 함께 봅니다. 다른 연도에 실행된 일지도 연결됩니다.
5. `보류`, `취소`, `계획 외 작업`은 완료 건수로 집계하지 않습니다. 연간 화면은 목표 연도, 일지는 실제 작업 날짜로 조회합니다.

## 자료 공유

**자료실 → 자료 올리기**에서 제목·분류·설명과 파일 또는 http/https 링크를 등록합니다. 사진·PDF·엑셀·워드·한글·TXT·CSV를 지원합니다. 사진은 화면에 표시하고 PDF는 브라우저 보기가 가능합니다. 그 외 문서는 원본 다운로드 후 해당 프로그램에서 엽니다. 비공개 자료 파일은 내려받기 요청마다 농장 권한을 검사합니다.

공유 링크는 외부 사이트의 링크입니다. 그 사이트의 접근 권한은 해당 서비스가 관리합니다. 농장 기록을 읽을 수 있는 사람에게만 보여도 외부 링크의 공개 범위가 바뀌지는 않습니다.

## 백업·복구

- 일반 목록의 **CSV**는 현재 검색 결과를 저장합니다. 관리자 **농장 관리 → CSV 내려받기**는 휴지통을 포함한 기록 목록을 저장합니다. 한글·날짜를 위해 UTF-8 BOM 형식을 사용합니다.
- **전체 백업 ZIP**은 기록·설정·참여자 역할·감사 목록과 첨부파일을 함께 저장합니다. 비밀번호·로그인 토큰·초대 코드 해시는 포함하지 않습니다. ZIP은 전체 파일 합계 100MB 이하에서 제공됩니다.
- 백업할 때 참여자에게 잠시 편집 중지를 알리고 최신 목록에서 실행하세요. 백업 중 변경을 발견하면 실패로 표시하므로 다시 실행합니다. 내려받은 백업을 개인 관리 장치와 별도 보관 장소에 이중 보관합니다.
- 100MB를 넘으면 PC에서 `scripts/backup.mjs`를 사용합니다. 관리자 계정으로 인증하며 큰 파일을 하나씩 내려받습니다. 예시는 아래와 같습니다. 환경변수 파일은 Git에서 무시되는 안전한 파일로 보관하고 공유하지 않습니다.

  ```bash
  # .env.backup에 프로젝트 URL·공개 키·관리자 이메일·비밀번호를 안전하게 설정
  node --env-file=.env.backup scripts/backup.mjs backups/2026-10-17
  ```

  필요한 변수 이름: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `FARM_EMAIL`, `FARM_PASSWORD`. 스크립트에는 값을 넣지 않습니다. 대상 폴더는 새 이름이어야 하며 부모 폴더를 먼저 만듭니다.

- CSV만으로 사진·권한까지 복구할 수는 없습니다. 파일을 포함하는 ZIP 또는 스크립트 백업을 보관하세요. 무료 플랜에는 본 앱의 자동 원격 백업 예약이 없습니다.

복구는 서비스 소유자/개발자가 **별도의 빈 프로젝트**에 수행합니다.

1. 백업 ZIP이라면 안전한 로컬 폴더에 풉니다. `manifest.json`과 `files/`가 있어야 합니다.
2. 새 Free 프로젝트에 앱 마이그레이션을 적용합니다. 아직 초기 관리자 SQL은 실행하지 않아 `members/entries/assets`가 비어 있어야 합니다.
3. 백업에 있는 참여자들의 Auth 계정을 새 프로젝트에 다시 생성합니다. 비밀번호는 백업하지 않으므로 새로 설정합니다. 이전 UUID를 키, 새 UUID를 값으로 하는 `user-map.json`을 만듭니다. 이전 참여자·비활성 계정도 기존 기록의 작성자 연결을 위해 대응시킵니다.
4. 새 프로젝트의 `SUPABASE_URL`과 **서버 전용** `SUPABASE_SERVICE_ROLE_KEY`를 안전한 환경변수로 공급하고 다음 명령을 실행합니다. 이 키를 프런트엔드·채팅·소스에 넣지 않습니다.

   ```bash
   node --env-file=.env.restore scripts/restore.mjs BACKUP_FOLDER user-map.json --empty-target-confirmed
   ```

5. 복구 도구는 비어 있지 않은 대상을 거부하고, 파일 크기·계정 대응과 스크립트 백업의 SHA-256을 확인합니다. 계정 매핑 후 기록·계획 연결·파일·역할을 복원합니다. 원래 감사 이력은 백업의 manifest에 남기고 새 DB에는 복구 작업 감사가 기록됩니다.
6. 두 계정으로 기록·사진·권한을 점검하고 마지막 관리자·열람자·접근 해제 설정을 확인한 뒤 화면의 공개 설정을 새 프로젝트로 연결합니다.

복구는 여러 서비스에 걸친 순차 작업으로, 중간 실패 시 전체 자동 롤백을 하지 않습니다. 운영 프로젝트를 덮어쓰지 말고 별도 빈 프로젝트에서 원인을 해결한 뒤 다시 복구하세요. 소유자가 보관한 원본 백업은 수정하지 않습니다.
