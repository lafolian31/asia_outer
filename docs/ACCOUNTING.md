# 함께그린 공동회계 운영·개발 안내

개발일: 2026-10-22. 개발 브랜치: `feature/shared-accounting`. 운영 주소는 https://asia-outer.pages.dev/ 이며, 이 문서 작성 단계에서는 공동회계를 운영 환경에 적용하지 않았습니다. 모든 개발 검증은 로컬 Supabase와 가상 거래로 진행했습니다.

## 화면과 저장 구조

기존 React 19·TypeScript·Vite·Supabase Auth/Postgres·Cloudflare Pages 구성을 재사용합니다. 새 서버나 D1은 필요하지 않습니다. 기존 메뉴에 **공동회계**를 추가하고 사이트맵에도 연결합니다. 기존 작업일지·농장계획의 입력/저장 방식은 바꾸지 않습니다.

화면 순서는 계좌정보 → 조회 기간·찾기 → 기간 수입/지출·마지막 확인 잔액 → 거래 카드 → 접어 둔 월별/분류별 합계입니다. 관리자에게만 계좌·총무·분류 설정을, 관리자/총무에게만 가져오기·분류/비고 수정·업로드 이력을 제공합니다. 모든 거래는 모바일에서도 카드로 표시합니다. 기존 글자 크기 설정을 그대로 적용합니다.

| 새 테이블 | 보관 내용 |
| --- | --- |
| `accounting_settings` | 계좌 명칭·번호·설정 버전 |
| `accounting_roles` | 기존 회원에 연결한 별도 총무 지정 |
| `accounting_categories` | 수입 5종·지출 6종 기본 분류 및 추가 분류 |
| `accounting_imports` | 파일 해시·형식·크기·열 번호·건수·업로드/취소 담당자와 시각 |
| `accounting_transactions` | 변경할 수 없는 은행 거래 필드, 별도 분류·비고·버전·취소 표식 |
| `accounting_import_items` | 원본 시트/행 번호·신규/중복/오류/제외 판단 |
| `accounting_audit` | 설정·총무 지정·가져오기·비고/분류 수정·취소 이력 |

사진 버킷에 금융 파일을 넣지 않습니다. 엑셀 원본 파일·원본 파일명·열 제목은 서버에 보관하지 않고 필요한 거래 값, 위치 번호와 SHA-256만 저장합니다. 거래내용은 문자열 원문을 유지하며 분류와 비고를 별도로 저장합니다. 거래 원본의 금액·일시·내용을 변경하는 API는 없고 DB 트리거에서도 수정이 차단됩니다.

## 권한

| 기능 | 일반 참여자·열람자 | 총무 | 관리자 |
| --- | --- | --- | --- |
| 거래 조회·검색·계좌 복사·은행 링크·보고서 | 가능 | 가능 | 가능 |
| 엑셀 가져오기·분류/비고 수정·오류 이력 | 불가 | 가능 | 가능 |
| 계좌 설정·총무 지정·분류 추가·업로드 취소·전체 감사 이력·백업 | 불가 | 불가 | 가능 |

기존 농장 관리자만 총무를 지정할 수 있습니다. 총무는 농장 기록의 관리자 권한을 얻지 않습니다. 농장 접근이 해제되면 기존 로그인 세션으로도 회계 API를 사용할 수 없습니다. 미로그인 방문자와 농장 비회원은 열람할 수 없습니다. 회원의 테이블 직접 조회/변경 권한을 모두 회수하고, 인증·활성 회원·역할을 검사하는 RPC만 노출합니다. 프런트에 비밀키를 추가하지 않습니다.

일반 회원에게 반환하는 거래내용/비고에는 긴 숫자열(전화·계좌 등)과 일부 한국어 이름을 서버에서 마스킹합니다. 이름 인식은 휴리스틱이므로 모든 개인정보를 완벽히 찾을 수 없으며 일반 단어가 가려질 수도 있습니다. 업로드 전에 불필요한 식별정보를 제거하고 거래내용에 민감정보를 쓰지 않는 운영이 필요합니다. 계좌번호는 송금을 위한 복사 기능 때문에 로그인 회원에게 전체를 표시합니다. 관리자/총무와 전체 백업에는 거래 원문이 포함됩니다.

## 가져오기와 중복 판단

1. 관리자: 공동회계 아래 **관리자 회계 설정**에서 모임통장 명칭과 계좌번호를 저장합니다. 필요하면 기존 회원을 총무로 지정합니다.
2. 관리자/총무: **거래내역 가져오기**에서 XLSX·XLS 또는 UTF-8 CSV를 선택합니다. 선택된 파일은 브라우저의 별도 Worker에서 읽습니다.
3. 시트·제목행을 선택하고 거래일자, 별도 시각(선택), 금액/입출금 구분 또는 입금액/출금액, 거래내용, 잔액(선택), 은행 거래 고유번호(실제로 제공되는 경우만)를 연결합니다. 원본 행 번호를 고유번호 열로 지정하면 안 됩니다.
4. **미리보기와 중복 검사**를 실행합니다. 신규·확실한 중복·오류·담당자 검토 행을 확인합니다. 오류는 원본 위치와 이유를 보여주며 저장에서 제외됩니다.
5. 겹친 파일의 의심 행마다 기존 거래와 중복인지, 실제 별도 거래인지, 이번에는 제외할지 선택합니다. 확인 체크 후 **확인한 거래 최종 저장**을 누릅니다.
6. 결과의 신규·중복 제외·오류·담당자 제외 건수를 확인합니다. 은행 원본 건수/합계와 대조합니다.

같은 파일 해시·시트·행의 같은 거래는 자동 중복 처리합니다. 같은 원본 행을 다른 열 연결로 해석하면 오류로 중단시킵니다. 실제 은행 고유번호가 같고 거래 필드도 같으면 중복이며, 값이 다르면 오류입니다. 다른 파일에서 일시·시간 정밀도·입출금·금액·원문·잔액이 같으면 담당자 검토가 필요합니다. 날짜와 금액만 같다는 이유로 제외하지 않습니다. 한 파일 안에서 완전히 같은 거래도 별도 실제 거래로 확인하면 모두 저장할 수 있습니다. 파일 안에서 은행 고유번호가 반복되면 뒤 행을 오류로 분리합니다.

저장 시 서버에서 형식/중복 검사를 다시 실행하고 단일 DB 트랜잭션·동시 업로드 잠금으로 처리합니다. 같은 업로드 재시도에도 합계가 늘어나지 않습니다. 다른 담당자가 먼저 저장해 판단이 달라지면 미리보기를 다시 실행해야 할 수 있습니다.

### 파일 제한과 실제 은행 파일 검수

- 실제 카카오뱅크 파일은 아직 제공되지 않았습니다. 범용 열 연결 기능을 구현했으며, 실제 원본 형식에 대한 최종 적합성 검수는 남아 있습니다.
- 파일 10MiB, 저장 거래 5,000행/회, 시트 20개, 시트당 5,100행·100열, 전체 60만 셀, 셀 2,000자 제한입니다. 은행 설명/제목행은 제목행 선택으로 건너뜁니다. 하단 설명행은 오류로 분리되므로 확인 후 제외하거나 필요한 거래만 별도 저장하세요.
- XLSX ZIP 항목 1,500개, 단일 압축 해제 항목 32MiB/전체 64MiB 제한을 선언값과 실제 해제량으로 검사하고 15초를 넘으면 Worker를 종료합니다.
- 암호 파일은 은행 암호를 입력받지 않습니다. 신뢰하는 PC의 엑셀에서 암호를 해제하고 매크로 없는 일반 XLSX로 다시 저장하세요. 파일 서명 불일치·매크로·수식 셀·손상 파일은 안내 후 차단합니다. CSV는 UTF-8로 다시 저장하세요.
- 날짜는 엑셀 1900/1904 일련번호, `YYYY-MM-DD`/점/슬래시/`YYYYMMDD`와 선택 시각을 지원합니다. 한국 은행의 현지 시각으로 저장하며 시간대 접미사나 임의의 날짜 표현을 추정하지 않습니다. 소수 원 금액은 오류입니다.
- 화면은 React 문자열로 출력하고 보고서의 모든 문자열은 엑셀 텍스트 셀로 만듭니다. 수식·HTML을 실행하지 않습니다.
- 서버에는 파일 자체를 보내지 않으므로 서버는 파일 형식/크기 메타데이터·정규화된 행·범위·권한을 검사합니다. 서버가 원본 바이너리를 다시 파싱하거나 은행이 발급한 진본인지 인증하는 기능은 없습니다. 업로드 담당자의 은행 원본 대조가 필요합니다.

파서는 Apache-2.0 라이선스의 SheetJS CE 0.20.3 배포 패키지 `@e965/xlsx@0.20.3`을 고정 사용합니다. 공식 CDN 접근이 이 환경에서 차단되어 npm 미러 배포를 사용했습니다. 2026-10-22 `npm audit --omit=dev` 결과 알려진 취약점 0건이었으며, 이는 모든 취약점이 없다는 보장은 아닙니다.

## 잔액·합계·보고서

수입/지출·월별·분류별 합계는 **선택 기간 안에 등록된 유효 거래**를 집계합니다. 입출금/찾기는 거래 목록에 적용하고 기간 합계와 혼동하지 않도록 화면에서 안내합니다. 모든 합계는 PostgreSQL 정수/정밀 합계이며 큰 합계는 문자열과 BigInt로 표시합니다.

**마지막 거래 기준 잔액**은 조회 기간과 별개로 은행 파일이 제공한 가장 최근 확인 잔액입니다. 수입에서 지출을 뺀 값을 은행 잔액으로 만들지 않습니다. 마지막 거래에 잔액이 없다면 이전에 확인된 잔액과 그 시각을 표시합니다. 동일 시각 잔액이 충돌하거나 일자만 있는 당일의 거래 순서가 불명확하면 잔액을 ‘확인 불가’로 표시합니다.

등록된 입출금 변화와 은행 잔액 변화가 맞지 않는 구간에는 누락/순서 점검 안내를 표시합니다. 일부 기간의 파일만으로 전체 계좌 내역의 완전성을 보장할 수 없습니다. 보고서도 등록된 자료에 한정되며 **선택기간 엑셀 보고서**로 요약·거래·월별·분류 시트를 내보냅니다(회당 10,000건까지). 영수증 첨부는 이번에 활성화하지 않았습니다. 추후 별도의 회계 접근 권한을 갖춘 비공개 저장 구조로 확장해야 합니다.

## 잘못된 업로드 취소

관리자는 **업로드·수정 이력 → 이 업로드 취소 검토**에서 사유를 쓰고 ‘취소’를 입력한 뒤 확정합니다. 원본 거래와 이력은 삭제하지 않고 해당 업로드에서 신규로 생성한 거래만 집계에서 제외합니다. 다른 유효 업로드가 해당 거래를 중복으로 참조하고 있으면 취소를 차단합니다. 참조하는 업로드를 먼저 확인하고 취소해야 합니다. 이후 수정한 은행 파일을 새 업로드로 미리보기하여 등록할 수 있습니다. 개별 은행 원본 필드의 직접 편집은 제공하지 않습니다.

계좌번호는 유효 거래가 존재하면 변경을 제한하여 서로 다른 통장의 거래/잔액 혼합을 막습니다. 명칭은 변경할 수 있습니다. 실제 통장을 변경할 때는 기존 회계 보존·새 원장 분리 방안을 먼저 마련해야 하며, 데이터를 삭제해 우회하지 마세요.

## 백업과 적용 순서

운영 반영은 사용자 승인 후 진행합니다. 기존 운영 DB를 초기화하지 않습니다.

1. 기존 앱의 **농장 관리 → 전체 백업**을 다운로드하고 안전한 장소에 별도 보관합니다. 대용량은 기존 `scripts/backup.mjs`를 보안 환경변수로 실행합니다. 운영 서비스 키나 비밀번호를 채팅/저장소에 올리지 않습니다.
2. Supabase SQL Editor에서 **`supabase/migrations/202610220001_accounting.sql` 한 파일 전체만** 실행합니다. 새 테이블 7개·기본 분류·RPC·원본 보호 트리거·권한을 추가합니다. 기존 농장 테이블/기록/사진/회원 역할은 삭제·변경하지 않습니다. 한 트랜잭션으로 실행되며 재실행 시 기존 데이터가 유지됩니다. 보호 트리거를 교체하는 구문 때문에 SQL Editor가 변경 경고를 표시할 수 있으며, 농장 데이터 삭제나 테이블 초기화 구문은 포함하지 않습니다.
3. Cloudflare Pages의 현재 공개 Supabase 설정을 유지하고 이 브랜치의 검토된 변경을 main에 병합·빌드하여 배포합니다. 새 환경변수·Workers·D1·은행 API 키는 필요 없습니다. 개발용 `.env.local`로 만든 `dist`를 운영에 올리지 않습니다.
4. 관리자 로그인 → 공동회계 → 계좌 등록 → 총무 지정 → 가상 소량 파일로 조회/쓰기 권한 확인 → 실제 파일을 비공개로 점검합니다. 실제 금융 자료는 GitHub나 정적 배포 파일에 넣지 않습니다.
5. 공개 회원 공유 전에 일반 회원·총무·관리자 및 접근 해제 계정으로 hosted API를 재검증하고 iPhone/iPad/Windows 실기기에서 사용을 확인합니다. 로컬 검증이 운영 설정을 대신하지 않습니다.
6. 문제 발생 시 프런트를 이전 배포로 되돌리면 기존 농장 기능을 계속 사용할 수 있습니다. 추가 회계 테이블과 저장 데이터는 보존합니다. 회계 삭제/DB 초기화로 되돌리지 않습니다.

적용 후 전체 백업에는 회계 설정·역할·분류·거래 원본·취소 상태·감사 이력도 포함되며 금융정보가 들어 있으므로 비공개로 보관합니다. 백업 도중 회계가 바뀌면 일관성 검사가 실패하여 다시 실행하도록 합니다. 보고서는 복구용 전체 백업의 대체물이 아닙니다.

복구는 모든 마이그레이션을 적용한 **별도의 빈 프로젝트**에서만 기존 `scripts/restore.mjs`를 사용합니다. 새 Auth 사용자 UUID 매핑을 먼저 준비하고 파일 해시/계정 매핑을 검사한 뒤 복구합니다. 기존 DB에 덮어쓰기를 금지하며, 복구 후 관리자/일반회원의 파일·회계 접근을 확인합니다. 회계만 부분 복구하는 관리 화면은 제공하지 않습니다.

## 무료 운영 확인

2026-10-22 공식 문서의 GitHub 원본을 다시 확인했습니다: [Supabase 무료 조건](https://github.com/supabase/supabase/blob/master/apps/docs/content/guides/platform/billing-on-supabase.mdx), [Pages 제한](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/pages/platform/limits.mdx). 현재 공개 조건은 Supabase DB 500MB/프로젝트·Storage 1GB·월 50,000 MAU·전송량 5GB, Pages 빌드 월 500회·정적 파일 개별 25MiB입니다. 자세한 기존 제약은 [무료 운영 안내](FREE_TIER.md)를 참고하세요.

공동회계는 기존 무료 Postgres/Auth와 정적 Pages를 사용합니다. 원본 엑셀을 Storage에 쌓지 않으며 추가 유료 서비스나 은행 연동을 활성화하지 않았습니다. 거래·인덱스·이력은 기존 DB 용량과 전송량을 소비합니다. 실제 운영 조직의 플랜과 남은 용량은 접근 권한이 없어 확인하지 못했으므로 배포 전에 소유자가 Supabase 사용량 화면에서 확인해야 합니다. 무료 한도·휴면 중지·수동 백업 조건은 계속 적용됩니다.

공식 카카오뱅크 홈페이지 `https://www.kakaobank.com/`만 연결합니다. 계좌 직행 공식 링크는 확인되지 않아 만들지 않았습니다. 이 환경에서는 해당 웹사이트 접속이 차단되어 실제 은행 페이지/앱 동작 확인은 사용자 기기에서 남아 있습니다.
